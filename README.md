# 🚌 Bus Route & Ticketing System

A console-based bus route booking application developed in **Java** to demonstrate how core Data Structures and Algorithms can be applied to a practical ticketing system.

The application manages bus routes, seat availability, passenger bookings, ticket searches, cancellations, and waiting lists. It uses a Circular Linked List, Queue, Two-Dimensional Array, HashMap, and File Handling.

## ✨ Features

- **View Bus Routes:** Display the stops for buses `B101` and `B102`.
- **Book a Seat:** Allocate the next available seat and generate a ticket ID.
- **Search Tickets:** Find a booking using its ticket ID.
- **Cancel Bookings:** Cancel a ticket and release its seat.
- **Waiting Queue:** Add passengers to a FIFO queue when a bus is full.
- **Automatic Seat Reassignment:** When a booked seat is released, assign it to the first passenger in that bus's waiting queue.
- **View Seats:** Display the booked/free status of a bus's seats.
- **Find Next Stop:** Look up the stop following a given route stop, including wrap-around from the final stop to the first.
- **File-Based Storage:** Load saved bus and ticket records at startup and save updated records when exiting.

## 🛠️ Data Structures and Concepts Used

| Data Structure | Application |
|---|---|
| Circular Linked List | Stores bus route stops, where the last stop points back to the first stop. |
| Two-Dimensional Array | Tracks seat occupancy for each bus (2 rows × 3 seats). |
| Queue | Maintains waiting passengers in First-In, First-Out (FIFO) order. |
| HashMap | Maps ticket IDs to ticket details for quick searching. |
| LinkedHashMap | Stores buses while preserving insertion order. |
| File Handling | Reads and writes route identifiers and ticket records in `bus_routes.txt`. |

### Ticket Cancellation

When a ticket is cancelled:
- The booked seat is released.
- The system checks the waiting queue.
- The first passenger in the queue receives the released seat.
- A new ticket ID is generated for that passenger.

## 💾 Data Persistence

The application uses a local text file named `bus_routes.txt`.

- `R|` records store bus identifiers.
- `T|` records store ticket ID, passenger name, bus ID, and seat number.

Saved route and ticket records are loaded when the application starts. Updated records are written when the user selects **Exit**.

**Note:** The current implementation does not save waiting-queue entries. Waiting passengers are held in memory and are not restored after the application is closed. Route stop lists are defined in the Java source code.
